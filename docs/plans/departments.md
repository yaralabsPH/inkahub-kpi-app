### Fixed storage and RPC contract

All six tables live in `public`; internal functions live in an unexposed `departments_private` schema. UUID primary keys use server-generated IDs. Department/person references use RESTRICT, never profile FKs. Server times are `timestamptz`; versions start at 1 and increment on actual changes.

| Table | Columns beyond its UUID `id` (unless specified) |
| --- | --- |
| `business_departments` | `name text`, globally unique `normalized_name text`, `archived_at timestamptz NULL`, `version bigint`, `created_at`, `updated_at`, `created_by uuid`, `updated_by uuid` |
| `business_department_names` | `department_id uuid`, `name text`, `valid_from`, `valid_to NULL`, `created_at`, `created_by uuid`, `request_id uuid`, `closed_at NULL`, `closed_by uuid NULL`, `closed_request_id uuid NULL` |
| `person_department_assignments` | `person_id uuid REFERENCES auth.users(id) ON DELETE RESTRICT`, `department_id uuid`, `valid_from`, `valid_to NULL`, `created_at`, `created_by uuid`, `closed_at NULL`, `closed_by uuid NULL`, `reason text`, `request_id uuid`, `closed_request_id uuid NULL` |
| `department_audit` | `request_id uuid`, `operation text`, `actor_id uuid NULL`, `department_id uuid NULL`, `person_id uuid NULL`, `assignment_id uuid NULL`, `recorded_at`, `effective_at`, `before_data jsonb`, `after_data jsonb`, `reason text` |
| `department_requests` | No separate `id`: PK `(actor_id uuid, request_id uuid)`; `payload_hash text`, `result jsonb`, `created_at` |
| `department_snapshot_control` | No UUID `id`: `singleton boolean PRIMARY KEY CHECK (singleton)`, `enabled boolean` initially false, immutable `tracking_started_at`, `version bigint`, `updated_at`, `updated_by uuid NULL` |

`department_audit.operation` is `create|rename|archive|restore|assign|transfer|correct|remove|control`. Assignment closure is included in the same transfer/correction/removal audit, not an extra successful-mutation count. Auth actor IDs are retained; `actor_id`/closing actor may be NULL only for a trusted lifecycle deletion without end-user claims. In that case record `reason='profile_removed_actor_unavailable'`; never claim the removed person or service role was the initiating owner. #8 uses a server client for removal, so this limitation must be visible in its acceptance evidence. Preserve its ban → barcode → locations → profile sequence.

Intervals are finite-start, finite-or-NULL-end UTC `[valid_from,valid_to)`, with `valid_to > valid_from`. GiST constraints `person_department_assignments_no_overlap` and `business_department_names_no_overlap` exclude `(person_id WITH =, tstzrange(valid_from,valid_to,'[)') WITH &&)` and `(department_id WITH =, range WITH &&)` respectively. Use `extensions.gist_uuid_ops` explicitly for UUID equality. Partial unique indexes `person_department_assignments_one_open` and `business_department_names_one_open` cover the corresponding subject where `valid_to IS NULL`. Concurrent overlap must fail in SQL, not only in a trigger. Retain assignments, labels, receipts and audits indefinitely; only closure metadata/end may update a historical interval.

Public RPCs (no overloads/default parameters; callers send explicit NULLs):

```sql
public.department_admin(
  p_operation text, p_request_id uuid, p_department_id uuid,
  p_person_id uuid, p_name text, p_expected_version bigint,
  p_expected_assignment_id uuid, p_reason text
) RETURNS jsonb
public.department_set_snapshot_enabled(
  p_request_id uuid, p_enabled boolean, p_expected_version bigint, p_reason text
) RETURNS jsonb
public.department_owner_page(
  p_kind text, p_subject_id uuid, p_cursor jsonb, p_limit integer
) RETURNS jsonb
```

- Admin operations: `create|rename|archive|restore|assign|correct`. Create takes name; rename takes department/name/expected department version; archive/restore take department/version; assign/correct take person/active target department/expected target version/expected current assignment ID (NULL means no home). Reject unrelated non-NULL arguments. No effective-time argument, clear-home action, delete or bulk import. Correction requires nonblank reason; other reasons may be empty. Control requires nonblank reason and expected control version.
- Every RPC authenticates and checks current owner role, including replay and reads. Validate finite positive versions, UUIDs, operation/field combinations, normalized 1–80 Unicode characters and reason length ≤500. Reject control characters before whitespace normalization; trim and collapse permitted whitespace, preserve display case, use database `lower()` for uniqueness across active and archived current names. Browser preview is advisory. Old names become reusable after rename.
- Mutation result: `{request_id, outcome: 'applied'|'noop', effective_at, department_id, department_version, assignment_id, control_version}` with inapplicable fields NULL, versions serialized as decimal strings. Hash canonical operation plus validated arguments (excluding request ID) using installed `pgcrypto`; receipt is keyed by actor/request. Reauthorize, lock, then return an identical stored receipt before checking stale expected versions. Different payload with the same key errors. No-op same-department assignment/unchanged rename/control returns a receipt without an interval, version bump or mutation audit. Mutation, audit and receipt commit together; exceptions leave none.
- All mutations, including profile removal and control, use **exclusive `pg_advisory_xact_lock(494749, 5)`**. Resolver uses **`pg_try_advisory_xact_lock_shared(494749, 5)`**. Reserve this two-int key for F5 and check the selected base for collisions; never substitute an F1/inventory lock. Admin/lifecycle wait is bounded by transaction-local `lock_timeout='2s'` (restore the prior setting on exit); no unbounded retries. Capture server effective time only after acquisition and re-read committed state in a separate VOLATILE query. Check expected versions/current assignment and current profile then. A non-increasing closure instant is a retryable conflict, never a zero-length interval or invented future effective time.
- Use SQLSTATE `42501` for unauthorized calls, `22023` for invalid input/reused key with changed payload, `40001` for stale expectations, `55P03` for bounded lock failure, and `23505` for name collision. Archive with open members uses `P0001`/fixed message `department_has_members`; fetch paginated members rather than embedding an unbounded list in the error. UI preserves input, offers same-ID retry for unknown outcomes/lock failure, and refresh plus deliberate new request after stale-version conflict.
- Read kinds: `departments_active|departments_archived|people|members|history|audit`. Subject is department ID for members, person ID for history, otherwise NULL. Return `{rows,next_cursor}`; department rows add `member_count`, people/members expose only Auth ID, display name, current assignment/department and date (no rates/email), history/audit use table fields above with “Removed person” fallback. People includes every current profile, including unassigned, without worker-role inference. Control is one owner-only direct SELECT. Limit defaults in the client to 50; SQL rejects outside 1–100. Keyset order: department/person UUID ascending; history `(valid_from,id)` descending; audit `(recorded_at,id)` descending. Cursor contains that complete tuple and is validated. Fetch counts/labels in a bounded query, never one request per member.

### Event and trigger contract

Task 4 adds these **nullable, no-default** event columns; no new event-table FKs: `business_department_id uuid`, `business_department_name text`, `business_department_assignment_id uuid`, `business_department_name_version_id uuid`, `business_department_status text`, `department_snapshot_version smallint`, and `department_occurred_at`, `department_received_at`, `department_resolution_instant`, `department_resolved_at` as `timestamptz`, plus `department_time_status text`.

Attribution vocabulary: `assigned|unassigned|before_tracking|invalid_time|resolution_busy|resolution_error|disabled|control_missing|resolver_unavailable`. NULL is legacy/never resolved. `assigned` has all four department/label references; every other status clears all four. Time vocabulary is independently `reported|future_clamped|reported_old|invalid_time`, with NULL only for legacy or guard-only inserts.

| Trigger → function in `departments_private` | Required behavior |
| --- | --- |
| `production_events_f5_10_sanitize` BEFORE INSERT → `sanitize_event()` | First F5 INSERT trigger. Overwrite every supplied F5 field; clear references, set version 1, copy `NEW.created_at` after its existing default to occurrence, capture `clock_timestamp()` once as receipt, set `resolver_unavailable`; resolution/time-status/attempt remain NULL. No helper/config/history lookup. |
| `production_events_f5_20_resolve` BEFORE INSERT → `resolve_event()` | VOLATILE, sets attempt time; classify O/S; read control with off/missing precedence while preserving classified time markers. Enabled: invalid → `invalid_time`; before tracking → `before_tracking`; unsupported isolation → `resolution_error`; failed try-shared lock → `resolution_busy`. After acquisition, one fresh VOLATILE query rechecks control and resolves assignment plus historical label/archive validity at the chosen instant, using `NEW.staff_id`, never `auth.uid()`. Zero assignments → `unassigned`; one complete consistent match → `assigned`; overlaps, missing label or inconsistent archive history → `resolution_error`. |
| `production_events_f5_10_freeze` BEFORE UPDATE → `freeze_event()` | Copy all eleven F5 fields from OLD, including all-NULL legacy. For non-NULL OLD status, reject `IS DISTINCT FROM` changes to `staff_id`, `created_at`, `location`, `id`; permit unrelated updates. Do not resolve again. |
| `profiles_f5_10_close_assignment` BEFORE DELETE → `close_profile_assignment()` | Under the exclusive F5 lock, close an open assignment at server time and audit atomically with profile deletion; no assignment is a no-op. Failure rolls back profile deletion. Retain Auth identity/history and accept trusted service-driven deletion without inventing an actor. |

Postgres fires same-event triggers in name order: catalog proof must show sanitize before resolve and no later BEFORE trigger rewriting snapshots; inspect all existing BEFORE UPDATE triggers for freeze compatibility. F1's `production_events_reporting_capture` is AFTER INSERT/UPDATE/DELETE and must see the final row once. It is untouched. Its missing-control exception can still abort the statement outside F5; report that to F1's owner.

Internal `departments_private.classify_time(p_occurred_at timestamptz,p_received_at timestamptz) RETURNS TABLE(time_status text,resolution_instant timestamptz)` is deterministic and not client-executable. O nonfinite (or defensive NULL) or O>S+5s gives invalid/NULL; 0<O−S≤5s gives clamped/S; S−O>5min gives old/O; otherwise reported/O. Keep `created_at` and occurrence verbatim. No maximum old age after tracking. Future-clamped lookup at receipt S remains historical even if a transfer commits between receipt and shared-lock acquisition. READ COMMITTED is required for resolution; other isolation levels save unknown, not stale credit.

Catch optional control/lookup failures in a sub-block, clear references and save `resolution_error`; sanitized warnings contain only a fixed error category and event key. Protect warning emission too. No network, audit write, event UPDATE or retry in insert triggers. Do not swallow outer RLS/constraint/F1 failures or statement cancellation. Guard-only inserts have no attempt time; all resolver attempts, including disabled/failure, do. Existing INSERT RLS, deletion/cancellation and inventory rules remain unchanged.
