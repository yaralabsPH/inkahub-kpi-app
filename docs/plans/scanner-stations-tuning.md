## Approach

Implement the approved [spec](../specs/scanner-stations-tuning.md) in the existing pure preparation/session modules, injected controller, and React wall. CJ approved the entire spec on 2026-11-25: three **additional** own-badge scans, at least one second apart, within ten seconds inclusive; suspicious framed lines reject the whole scan; A0 preparation uses framing lines only; corruption recovery applies to both shared modes. The spec's remaining draft/proposal wording is historical, not a request to reopen these decisions. The A0 accessory packing/stock procedure remains a **pre-release** question below.

`order.ts` currently rejects blank/unknown/canvas lines before selecting framing, routes accessories into A0 components, and gives all lines to F4 packaging. Add a scanner-local classifier, then use its selected subset consistently for new Framing preparation. Keep `orderHeaderProblem`, the global SKU grammar, shared packaging helpers and Dispatch preparation unchanged. `client.ts:processNext` already prepares only queued jobs and reuses stored prepared payloads; preserve that boundary and prove old payloads still replay exactly.

`session.ts` owns identity and captures workers synchronously; `station.ts` owns asynchronous activation, durable enqueue and result display. Give the controller a receiver-wide recovery state separate from `last`, guarded by scan ordering so old completions cannot dismiss it. Put Framing gesture state in the pure session model with independent cancellation of gesture progress and badge activation. Wire progress and suppression into each scanner tile, so another scanner's traffic cannot hide the instructions. Existing keyed station remounts remain the account/site/receiver/mode reset boundary.

**No migration is required.** `0055_scanner_stations.sql` accepts the existing `p_lines`, `p_components`, `p_packaging` contract; filtering the client payload requires no schema or RPC change. Keep all migrations, `Repository.ts`, `DexieRepo.ts`, `SupabaseRepo.ts`, outbox schema and server endpoints unchanged. Shared production remains Supabase-only; Dexie here is durable device queue storage. No dependencies, environment variables or new top-level folders.

### Review focus

- An error can occur while an older badge check or queue write is unresolved, including in the same millisecond. Task 3 uses event ordering, not timestamps alone.
- A cancelled repeat sequence can still have a valid activation in flight. Task 5 prevents the reply from restoring gesture progress without cancelling legitimate activation merely because input was corrupt.
- A held badge can keep reading through activation and immediately after sign-out. Task 5 retains the rolling read guard across these transitions.
- Explicit non-framing products can contain the word “framed”; legacy/blank framed lines can have no valid SKU. Task 1 pins exclusion precedence and refusal evidence.
- An old A0 job may already have sent accessory deductions. Task 2 proves exact replay without reclassification, including after reload and uncertain outcomes.

- Staging reference: follow every step of [the approved spec's Staging test plan](../specs/scanner-stations-tuning.md#staging-test-plan) on **inka-staging-2**, then [release smoke tests](../RELEASING.md#2-smoke-test-staging-preview-about-10-minutes). Owner/manager inspects exact event quantities, components, boxes, unchanged original Shopify lines, clock-in deduplication/no clock-out, health and classic fallback. Staff/CS/anonymous/cross-site callers remain denied in UI/RPC checks.
- Server regressions: CJ uses the existing guarded staging scanner/dispatch assertions and race instructions against the already-migrated staging database; do not follow their historical migration-install step as a new deployment requirement. Preserve tests of old accessory-inclusive payloads, A0 packaging failure rolling back all credit/stock, partial/already-recorded refusal, classic/shared races and lost-response replay. - Manual release order: CJ records the current Vercel deployment, chooses a quiet period, merges/releases under `docs/RELEASING.md`, refreshes receiving tablets, starts sound/wake and checks mode/site/badge binding. **No new env vars, SQL, Shopify, Make, Slack or Edge Function settings.** Monitor the first thirty minutes for blocked/uncertain jobs, wrong attribution, missing stock/boxes and clock events.
